# Six Fighter — 镜头视窗规则文档

> **文档用途**：定义游戏的镜头架构、视窗系统、深度排序和渲染分层规则。所有美术资源生成、场景搭建、代码实现均须遵循本规则。
>
> **版本**：v1.0
> **日期**：2026-05-21
> **视角方案**：斜45°俯视角（Isometric-ish Top-Down），纯美术视角

---

## 第一章：核心视角定义

### 1.1 实现路线

本项目采用 **纯美术视角** 方案：

- 引擎保持标准 2D，不做任何投影变换
- "斜45°俯视角" 通过美术资源的绘制风格实现
- 世界坐标系 = 屏幕坐标系（1:1，无缩放/旋转）
- TileMap 使用正方形瓦片（Square Tiles），世界空间为标准网格

> **不采用引擎变换方案**：不对 Camera2D 或场景根节点做 Y 轴缩放。所有坐标、碰撞、物理均为标准 2D 计算。

### 1.2 视角参数（美术指导）

以下参数用于指导美术资源制作，不涉及引擎实现：

| 参数 | 值 | 说明 |
|------|-----|------|
| 垂直俯仰角 | ~45° | 从水平线向下倾斜观察 |
| 水平旋转角 | 0° | 摄像机正对下方（南方） |
| 投影方式 | 正交（无透视畸变） | 远近物体大小一致 |
| 光源方向 | 左上方 | 阴影落在右下方 |

### 1.3 视觉描述

玩家从角色的斜后上方观察世界：
- 能看到角色的**头顶 + 正面躯干**
- 地面向画面下方延伸
- 远处物体（Y值小）在画面上方
- 近处物体（Y值大）在画面下方，覆盖远处物体

### 1.4 技术基础

| 参数 | 值 |
|------|-----|
| 引擎 | Godot 4.6 |
| 视口尺寸 | 540 × 960 (9:16 竖屏) |
| 世界空间 | 远大于视口，支持大场景滚动 |
| 坐标系统 | 世界坐标，所有单位/投射物在世界空间中定位 |
| 渲染 | Camera2D 负责世界→屏幕的变换 |
| 拉伸模式 | `canvas_items` + `expand` |
| 纹理过滤 | 最近邻（Nearest Neighbor），像素风 |

## 第二章：镜头系统架构

### 2.1 锚点-跟随系统

```
┌───────────────────────────────────────────────┐
│                  场景世界                        │
│                                                 │
│    ┌───────┐    软跟随      ┌──────────┐       │
│    │ 英雄A  │◄──────────────┤          │       │
│    └───────┘               │  镜头锚点  │       │
│    ┌───────┐    软跟随      │ (Anchor)  │◄──────┤◄── 玩家输入（摇杆/WASD）
│    │ 英雄B  │◄──────────────┤          │       │
│    └───────┘               └────┬─────┘       │
│    ┌───────┐    软跟随           │              │
│    │ 英雄C  │◄──────────────     │              │
│    └───────┘                    │ 硬跟随        │
│                           ┌────▼─────┐         │
│                           │  主镜头   │         │
│                           │ (Camera2D)│         │
│                           └──────────┘         │
└───────────────────────────────────────────────┘
```

#### 镜头锚点（CameraAnchor）
- 一个 Node2D，位于世界空间中
- 接受玩家摇杆/WASD 输入，在世界空间中移动
- 移动速度固定，不受游戏逻辑影响
- 有场景边界限制，不越过地图边缘

#### 英雄单位（Hero）
- 每个英雄拥有自身位置和 AI 逻辑
- 目标是"跟随"镜头锚点，但在软跟随半径内自由活动
- 英雄位置 = 镜头锚点 + 阵型偏移 + AI 偏移
- AI 偏移允许英雄在战斗中出于战术原因偏离阵型位置（躲避、追击等）

#### 主镜头（Camera2D）
- 每一帧将其 global_position 设置为锚点位置
- 带平滑跟随（position_smoothing_speed = 5.0）
- 包含 trauma-based 屏幕震动功能

### 2.2 核心参数表

| 参数 | 值 | 说明 |
|------|-----|------|
| 视口尺寸 | 540 × 960 | 竖屏 9:16 |
| 锚点移动速度 | 250 px/s | 摇杆/WASD 控制镜头移动 |
| Camera2D 平滑跟随 | 5.0/s | position_smoothing_speed |
| 英雄跟随 lerp 速度 | 3.0/s | 正常跟随插值系数 |
| 英雄紧急追赶速度 | 8.0/s | 超出软半径后的快速插值 |
| 软跟随半径 | 350 px | 英雄围绕锚点的最大自由活动半径 |
| 硬边界阈值 | 480 px | 超过此距离触发强制传送 |
| 阵型中心 Y 偏移 | +100 ~ +150 px | 阵型整体向下偏移，英雄位于画面偏下区域 |

### 2.3 阵型定义（斜向排列）

3 人小队默认阵型，采用斜向排列模拟 45° 纵深感（锚点相对坐标）：

```
              锚点 (0, 0)     ← 屏幕几何中心
                │
         英雄B (-40, -40)     ← 前排（偏上方）
        ╱
  英雄A (-40, +40)            ← 后排左
        ╲
         英雄C (+40, +40)     ← 后排右

  + Y轴偏移 100~150px（整体下移）
```

- **前排（英雄 B）**：位于锚点左上方，是队伍的"尖端"
- **后排（英雄 A、C）**：位于锚点左下方和右下方，形成三角形底边
- 阵型中心整体向下偏移 100~150px，使英雄视觉上位于画面中心偏下

> **45° 视角注意**：由于视角倾斜，世界坐标中等距的点在画面上不等距。后排英雄的视觉间距会比前排略宽，这正是 45° 透视感的体现。美术资源应配合此阵型绘制角色朝向。

### 2.4 拉回机制

```
距离锚点            状态            处理方式
  0 ~ 350 px     正常           无干预，英雄自由活动
  350 ~ 480 px   超限           英雄启用紧急追赶 (lerp 8.0/s)
  > 480 px       越界           直接设置英雄位置到锚点 + 阵型偏移
```

**紧急追赶**：
- lerp 系数从 3.0 切换为 8.0
- 英雄以"跑步"动画快速返回
- 回到 350px 半径内后 lerp 系数切回 3.0

**强制传送**：
- 瞬间将英雄 global_position 设为 `anchor_position + formation_offset + y_bias`
- 触发闪烁/烟雾 VFX 掩盖突兀感
- 记录日志便于调试

## 第三章：深度排序规则（Y-Sort）

### 3.1 核心规则

**所有可渲染对象按世界坐标的 Y 值排序，Y 值越大的对象越靠近摄像机（画面下方），最后渲染，覆盖在上方。**

```
渲染顺序示意：

  画面顶部（远处，Y值小）
    角色A (y=100)  ← 先渲染（在后）
    角色B (y=200)  ← 后渲染（在前，覆盖A）
  画面底部（近处，Y值大）
```

### 3.2 排序细则

| 情况 | 排序规则 |
|------|---------|
| 不同 Y 值 | Y 值大的后渲染（在前） |
| 相同 Y 值 | X 值大的后渲染（右侧优先在前） |
| 动态对象 | 每帧更新排序（Godot Y Sort 自动处理） |

### 3.3 Godot 实现

- 场景树中对需要排序的父节点开启 **Y Sort** 属性
- 子节点自动按 Y 坐标决定渲染顺序
- 不需要手动设置 `z_index`（Y Sort 节点覆盖 z_index）
- 需要固定层级的对象（如 UI、全屏特效）放在独立的 CanvasLayer 中，不参与 Y Sort

### 3.4 哪些对象参与 Y Sort

| 参与 Y Sort | 不参与 Y Sort |
|------------|--------------|
| 英雄 | 地面纹理（TileMap 层） |
| 敌人 | 地面装饰 |
| 建筑底面 | 伤害数字（CanvasLayer） |
| 地面阴影 | 技能气泡（CanvasLayer） |
| 角色身上特效 | 全屏特效（CanvasLayer） |

## 第四章：渲染分层体系

### 4.1 层级定义

所有渲染对象按以下层级组织，使用 `z_index` 控制同层内的排序：

| 层级 | 内容 | z_index | Godot 实现 |
|------|------|---------|-----------|
| Layer 0 | 地面纹理（草地、泥土、地板） | 0 | TileMap 底层 |
| Layer 1 | 地面装饰（碎石、水洼、花草） | 5 | TileMap 装饰层 |
| Layer 2 | 地面痕迹（血迹、脚印、技能残留） | 10 | Node2D + z_index=10 |
| Layer 3 | 角色/怪物阴影 | 20 | Sprite2D + z_index=20 |
| Layer 4 | 角色/怪物实体 | 30 | **Y Sort 容器内** |
| Layer 5 | 建筑/障碍物底面 | 35 | Y Sort 容器内（与角色同层竞争） |
| Layer 6 | 建筑/障碍物主体 | 40 | z_index=40（遮挡角色） |
| Layer 7 | 飞行道具/投射物/弹道 | 50 | Node2D + z_index=50 |
| Layer 8 | 技能特效（爆炸、光环、治疗） | 60 | Node2D + z_index=60 |
| Layer 9 | 伤害数字/飘字 | 70 | **独立 CanvasLayer** |
| Layer 10 | 技能名称气泡/头顶 UI | 80 | **独立 CanvasLayer** |
| Layer 11 | 全屏特效（暗角、震动） | 100 | **独立 CanvasLayer** |

### 4.2 CanvasLayer 分离

以下内容**必须**放在独立的 CanvasLayer 中，不受 Camera2D 变换影响：

| CanvasLayer | 内容 | 用途 |
|-------------|------|------|
| UI Layer (layer=10) | 伤害数字、飘字、技能气泡 | 始终固定在屏幕空间 |
| HUD Layer (layer=20) | 血条、状态图标、摇杆、波次标签 | 游戏 UI |
| VFX Layer (layer=30) | 全屏暗角、屏幕震动叠加 | 全屏后处理效果 |

> **注意**：Layer 0-8 的对象在游戏世界中，受 Camera2D 变换影响。Layer 9-11 在屏幕空间中，不受镜头影响。

### 4.3 场景树结构参考

```
BattleScene (Node2D)
├── Ground (TileMapLayer)              # Layer 0-1
├── GroundDecals (Node2D)              # Layer 2, z_index=10
├── Shadows (Node2D)                   # Layer 3, z_index=20
├── YSortContainer (Node2D, Y Sort)    # Layer 4-6, 自动排序
│   ├── Hero A
│   ├── Hero B
│   ├── Hero C
│   ├── Enemy 1
│   ├── Enemy 2
│   └── Building (底面部分)
├── BuildingTops (Node2D)              # Layer 6, z_index=40
├── Projectiles (Node2D)               # Layer 7, z_index=50
├── VFX (Node2D)                       # Layer 8, z_index=60
├── DamageTextLayer (CanvasLayer, layer=10)   # Layer 9
├── HUDLayer (CanvasLayer, layer=20)          # Layer 10
└── FullscreenVFXLayer (CanvasLayer, layer=30) # Layer 11
```

## 第五章：场景边界与镜头限制

### 5.1 镜头锚点边界

- 镜头锚点不能移出地图边界
- 当锚点到达边界时，镜头停止移动，英雄仍可在屏幕内活动
- 超出场景部分的视口内容留黑或显示边界装饰

### 5.2 场景边界遮挡

地图边缘用树木、岩石、悬崖等自然物体遮挡，避免玩家看到地图边界。

## 第六章：特殊镜头效果

### 6.1 效果参数表

| 效果 | 触发条件 | 参数 |
|------|---------|------|
| 屏幕震动 | 角色受重击 / BOSS 登场 / 大型技能命中 | 偏移 2~5 px，持续 0.2~0.5 s |
| 缩放拉近 | 剧情对话 / 重要事件 | 从 1.0 缩放到 1.2，持续 0.5 s |
| 暗角 | 进入洞穴 / 夜晚场景 | 画面四角叠加黑色渐变遮罩 |
| 技能特写 | 释放终极技能 | 冻结画面 0.1 s 后恢复 |

### 6.2 震动实现（Trauma System）

VFX 系统通过 `camera.add_trauma(strength)` 调用屏幕震动。Camera2D 需要自定义脚本实现 trauma 系统：

- `add_trauma(value)`：累积创伤值（0.0 ~ 1.0）
- 每帧按衰减率减少 trauma
- 震动偏移 = trauma² × max_offset（二次方曲线，高创伤震动剧烈但衰减快）
- 创伤值归零后停止震动

## 第七章：视口适配规则

### 7.1 基准分辨率

以 **540 × 960** 为设计基准。所有游戏逻辑（敌人生成区域、英雄活动范围、阵型偏移等）以此为安全参考。

### 7.2 拉伸行为

| 设置 | 值 | 效果 |
|------|-----|------|
| stretch/mode | `canvas_items` | 画布缩放适配窗口 |
| stretch/aspect | `expand` | 扩展模式，不裁剪 |

- **比 9:16 更宽的屏幕**（如平板）：上下保留，左右多露出游戏区域
- **比 9:16 更窄的屏幕**（如某些手机）：左右保留，上下多露出游戏区域
- **设计原则**：额外可见区域是"奖励空间"，不放置关键游戏元素

### 7.3 UI 安全区

UI 元素（摇杆、血条、标签等）应使用锚点（Anchor）布局，确保在不同屏幕比例下位置正确。

## 第八章：角色与场景物体规范（核心摘要）

> 详细美术制作规范将在后续单独文档中定义。本节仅列出与镜头/渲染直接相关的核心规则。

### 8.1 角色锚点

- **锚点位置**：脚底中心，即角色与地面接触点的正中心
- **Godot 设置**：Sprite2D 的 `offset` 或 `centered = false` + 位置调整
- **阴影**：每个角色脚下有椭圆阴影，阴影中心与锚点重合

### 8.2 建筑锚点

- **锚点位置**：底面中心（与地面接触面的几何中心）
- **遮挡关系**：角色 Y 坐标 < 建筑锚点 Y 坐标时，建筑遮挡角色；反之角色遮挡建筑
- **碰撞区域**：建筑底面在地面上的投影，与视觉表现分离

### 8.3 角色朝向系统

角色支持 **4 方向** 朝向：

| 角度范围 | 量化方向 | 动画后缀 |
|----------|----------|----------|
| -45° ~ 45° | 右 (Right) | `_right` |
| 45° ~ 135° | 下 (Down) | `_down` |
| 135° ~ 225° | 左 (Left) | `_left` |
| 225° ~ 315° | 上 (Up) | `_up` |

朝向决定规则：

| 状态 | 朝向逻辑 |
|------|---------|
| 空闲 | 保持上一个有效朝向 |
| 行走 | 移动方向向量量化结果 |
| 施法 | 朝目标方向量化结果 |
| 受击 | 保持当前朝向 |

> **45° 视角优先级**：优先保证面向下方（正面）和面向右下方（斜侧面）的动画质量，因为这两个方向在画面中最常出现。

### 8.4 投射物方向系统

**投射物方向与角色方向完全解耦：**

- 角色朝向：4 方向量化（受限于精灵动画）
- 投射物飞行：**360° 自由方向**（纯数学计算，无资源限制）

投射物轨迹类型：

| 轨迹 | 说明 |
|------|------|
| 直线 | 沿精确方向匀速飞行 |
| 追踪 | 实时更新朝向目标的方向向量 |
| 贝塞尔曲线 | 控制点偏移的弧形轨迹 |
| 正弦波 | 直线叠加垂直正弦偏移 |
| 螺旋 | 直线叠加旋转偏移 |

### 8.5 角色尺寸参考

| 参数 | 值 | 说明 |
|------|-----|------|
| 角色高度 | ~48 ~ 55 px | 视口高度的 1/10 ~ 1/12 |
| 视口基准 | 540 × 960 | 角色尺寸以此为参考 |

> 此尺寸为初始基调，后续根据实际视觉效果可调整。

## 第九章：边界情况处理

### 9.1 场景边界

镜头锚点不应越过场景物理边界。当锚点被边界阻挡时：
- 镜头贴边，适当露出暗边或由关卡美术内容填补
- 超出场景部分的视口内容留黑或显示边界装饰

### 9.2 英雄全部死亡

所有英雄死亡后：
- 镜头锚点停止响应玩家输入
- 保持死亡时的最后位置
- 等待复活/重开逻辑

### 9.3 BOSS 战特殊处理

BOSS 战时可临时调整：
- 软跟随半径可缩小（迫使队伍更紧密）
- 锚点移动速度可降低（BOSS 战更注重走位精度）

### 9.4 多英雄同步

所有英雄的坐标以世界空间为基准，不依赖屏幕位置。多英雄在锚点周围的分布由各自的 AI 偏移 + 阵型偏移叠加决定，天然支持异步行为。

| 角色朝向 | 4 方向（上/下/左/右） |
| 投射物方向 | 360° 自由方向 |
