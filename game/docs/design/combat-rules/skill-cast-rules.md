# 技能释放规则 v2.0

## 一、核心设计原则

1. **独立触发**：每个小技能独立判断是否释放，互不干扰
2. **综合判断**：CD + 目标规则，全部满足才触发
3. **排队释放**：多个技能同时满足条件时，排队执行（间隔0.2秒）
4. **目标内禀**：目标选择逻辑是技能的内禀属性，外围模块只能调用，不能改写
5. **普攻兜底**：普攻只在所有小技能都在CD时才触发

## 二、技能槽位结构

每个英雄固定4个技能槽位：

| 槽位 | 类别常量 | 说明 |
|------|----------|------|
| BASIC | CAT_BASIC (0) | 普攻，低伤害高频 |
| SMALL_A | CAT_SMALL_A (1) | 小技能A，中等CD |
| SMALL_B | CAT_SMALL_B (2) | 小技能B，中等CD |
| ULTIMATE | CAT_ULTIMATE (3) | 大招，怒气触发 |

**关键规则**：small_a 和 small_b 是同一档次的"小技能"，各自独立CD，独立触发，无优先级关系。

## 三、技能释放流程

### 3.1 每帧tick流程

```text
tick(dt):
  1. 更新CD计时器（basic, small_a, small_b -= dt）
  2. 累加怒气（通过伤害积累）
  3. 独立检查小技能和大招：
     ┌─ ultimate: 怒气>=rage_cost + 有目标 → 加入队列
     ├─ small_a:  CD<=0 + 有目标 → 加入队列
     └─ small_b:  CD<=0 + 有目标 → 加入队列
  4. 如果小技能全在CD，才检查普攻：
     └─ basic: CD<=0 + small_a在CD + small_b在CD + 有目标 → 加入队列
  5. 从释放队列取出一个技能执行（间隔0.2秒）
```

**普攻触发条件**：只有当 small_a 和 small_b 都在CD中时，才允许普攻触发。

### 3.2 释放判断条件

每个技能释放需要同时满足：

| 条件 | 说明 |
| --- | --- |
| CD就绪 | timer <= 0（小技能/普攻）或 rage >= rage_cost（大招） |
| 有目标 | 调用技能自身的目标选择逻辑，返回有效目标 |

### 3.3 目标选择规则 (target_mode)

**核心原则**：目标选择逻辑是技能的内禀属性，由 SkillDef 定义。外围模块（RoleAI、CombatMediator）只能调用技能的目标选择方法，不能自行定义或改写目标选择逻辑。

| 值 | 枚举 | 选择逻辑 |
| --- | --- | --- |
| 0 | NEAREST | 距离最近的敌人 |
| 1 | FARTHEST | 距离最远的敌人 |
| 2 | LOWEST_HP | 当前血量最低的敌人 |
| 3 | HIGHEST_HP | 当前血量最高的敌人 |
| 4 | RANDOM | 随机选择 |
| 5 | ALL | 全部（技能自行处理多目标） |
| 6 | MAX_COVERAGE | 最大覆盖（技能自行处理） |

**调用方式**：外围模块调用 `skill_def.find_target(hero_pos, enemies)` 返回目标，不参与目标选择的具体逻辑。

## 四、释放队列机制

### 4.1 队列结构

```text
CastQueue:
  queue: Array[AutonomyPick]  # 待释放队列
  queue_timer: float          # 队列间隔计时器
  QUEUE_INTERVAL := 0.2       # 间隔时间（秒）
```

### 4.2 队列行为

1. **入队**：技能满足条件 → 加入队列末尾
2. **出队**：队列非空 + timer<=0 → 取出队首执行
3. **间隔**：每次出队后重置timer为0.2秒
4. **优先级**：队列内按入队顺序执行（FIFO），不做优先级排序

### 4.3 特殊情况

- **队列满**：无上限，但正常情况下队列长度不会超过2-3
- **清空**：英雄死亡时清空队列
- **打断**：眩晕状态不清空队列，但暂停出队

## 五、怒气系统

### 5.1 怒气获取

两个来源：**攻击怒气**和**受伤怒气**。

**攻击怒气**：造成伤害时获得怒气

- 公式：`rage += damage * rage_gain_rate`
- 统一系数：`rage_gain_rate = 2.0%`

**受伤怒气**：受到伤害时获得怒气

- 公式：`rage += damage_taken * damage_taken_rage_rate`
- 每个英雄独立系数（见下表）

| 英雄 | damage_taken_rage_rate | 设计理由 |
| --- | --- | --- |
| ember | 0.3% | DPS定位，不依赖受伤攒怒 |
| moss | 0.6% | 辅助定位，适度受伤攒怒 |
| ironwall | 1.0% | 前排坦克，频繁受伤需更快攒怒 |

**怒气上限**：100

### 5.2 满怒时间预估

假设战斗中英雄每秒受到伤害约100 DPS：

| 英雄 | 攻击怒气/秒 | 受伤怒气/秒 | 总怒气/秒 | 满怒时间 |
| --- | --- | --- | --- | --- |
| ember | 5.8 | 0.3 | 6.1 | 16.4秒 |
| moss | 3.78 | 0.6 | 4.38 | 22.8秒 |
| ironwall | 2.94 | 1.0 | 3.94 | 25.4秒 |

### 5.3 怒气消耗

- 大招释放时消耗全部怒气（rage = 0）
- 不消耗其他资源

## 六、CD管理

### 6.1 CD计时器

```text
AutonomyTimers:
  basic: float    # 普攻CD
  small_a: float  # 小技能A CD
  small_b: float  # 小技能B CD
  rage: float     # 怒气值（不是CD，是资源）
```

### 6.2 CD更新

每帧执行：`timer -= dt`（basic, small_a, small_b）

### 6.3 CD重置

技能释放时：`timer = skill_def.cooldown`

## 七、眩晕状态处理

- 眩晕时：停止CD递减，停止怒气获取，停止技能释放
- 眩晕结束：恢复正常逻辑
- 判断方法：`hero.status_effects.is_stunned()`

## 八、与旧版本的关键差异

| 项目 | 旧版本 | 新版本 |
| --- | --- | --- |
| 触发模式 | 选择器（每次选一个最好的） | 独立触发（每个技能独立判断） |
| small_a/small_b关系 | 有优先级（DPS先A，FRONTLINER先B） | 无优先级，独立触发 |
| 目标选择 | 外围模块自己定义逻辑 | 技能内禀属性，外围只能调用 |
| 释放机制 | 立即释放 | 排队释放（间隔0.2秒） |
| 大招触发 | 怒气满就释放 | 怒气满 + 有目标才释放 |
| 普攻触发 | 无特殊限制 | 仅当所有小技能在CD时才触发 |
| 怒气获取率 | 固定15% | 根据DPS动态计算，目标20秒满怒 |
